# 脸罩 FaceCover

[![自检](https://github.com/myCode-home/face_cover/actions/workflows/ci.yml/badge.svg)](https://github.com/myCode-home/face_cover/actions/workflows/ci.yml)

一个 macOS 小工具：录视频的时候，用一张图片盖住自己的脸，可以连系统里正在放的音乐一起录下来，
录完在「录像库」里统一回看。

打开摄像头 → 自动找到你的脸 → 把选好的图片贴上去 → 直接录成一个 `.mov` 文件。
**图片是合成进视频画面再编码的**，所以录出来的文件里脸是真的被挡住了，不是靠屏幕上的贴纸糊上去。

---

## 装 / 跑

**普通使用**：双击 `dist/FaceCover-<版本>.dmg`，把「脸罩 FaceCover」拖进「应用程序」。
（已经装好了：`/Applications/FaceCover.app`）

**自己改代码**：

```bash
./build.sh          # 只编译，产出 dist/FaceCover.app
./package.sh        # 生成图标 → 编译 → 跑自检 → 出 DMG 和 ZIP
./test.sh           # 只跑自检
```

只需要 macOS 自带的 Command Line Tools，**不需要装完整的 Xcode**。

### 分发

`./package.sh` 会产出两个文件（版本号取自 `Resources/Info.plist` 的
`CFBundleShortVersionString`，发版前记得改）：

| 文件 | 用途 |
|---|---|
| `dist/FaceCover-<版本>.dmg` | 双击挂载，拖进「应用程序」 |
| `dist/FaceCover-<版本>.zip` | 发给别人 |

> ⚠️ 这个 App 是**本地 ad-hoc 签名**的。在你自己这台机器上直接能用；
> 但如果通过微信/网盘发给别人，对方 macOS 会拦下来说「无法验证开发者」。
> 对方可以右键点 App → 「打开」→ 再点一次「打开」，或者执行
> `xattr -d com.apple.quarantine /Applications/FaceCover.app`。
> 要彻底解决得买苹果开发者账号做公证（notarization）。

## 权限

第一次打开会弹权限窗口，按需要允许：

| 权限 | 什么时候需要 | 不给会怎样 |
|---|---|---|
| 摄像头 | 一直需要 | 用不了 |
| 麦克风 | 声音来源选了「麦克风」或「两个都要」时 | 只能录画面或系统声音 |
| **屏幕录制** | 声音来源选了「系统声音」或「两个都要」时 | 录不到系统声音 |

> **为什么录个系统声音要「屏幕录制」权限？**
> macOS 没有提供只录系统声音的接口，ScreenCaptureKit 是唯一入口，而它统一归在「屏幕录制」权限下。
> 我们只添加了音频输出、不加画面输出，并且把屏幕捕获尺寸压到 2×2、帧率压到 1fps，基本不产生开销。
> 授权后需要**重启 App** 才生效。

要是误点了「不允许」：到「系统设置 → 隐私与安全性 → 摄像头 / 麦克风 / 屏幕录制」里把「脸罩 FaceCover」勾上，
再重开 App。App 里也有一个直接跳转到「屏幕录制」设置页的按钮。

> ⚠️ 每次重新 `./build.sh` 都会改变 App 的签名指纹，macOS 可能把新版本当成一个新 App 重新问你一次权限。这是正常现象。

## 怎么用

1. 点 **内置脸罩** 展开二级列表，11 款里挑一个；也可以点 **自定义图片**，或者直接把图片拖到左边的预览画面上
   （建议用正方形 PNG、背景透明，比如表情包、卡通头像、贴纸）
2. 图片会自动跟着你的脸动。大小/位置不合适就用右边的滑块微调
3. 在「声音来源」里选要录什么
4. 点 **开始录制**（或按 `⌘↩`），再点一次停止
5. 视频存到 `~/Movies/FaceCover/`
6. 点 **录像库** 打开列表回看（录完会自动刷新，不用手动点）

## 录像库

单独一个窗口，可以边录边看。每一条显示：

- **首帧缩略图**（点一下直接播放）
- 录制时间和文件名
- 时长、文件大小
- **播放** 按钮；`⋯` 菜单里有「在访达中显示 / 复制文件路径 / 删除」

删除是**移到废纸篓**，不是永久删除，误删还能捞回来。右键行也有同样的菜单。

顶部有刷新按钮、总数量和总大小。`~/Movies/FaceCover/` 里的 `.mov` 都会被列出来，
所以你自己拖进去的文件也会出现。

## 面板上的开关

| 选项 | 说明 |
|---|---|
| 内置脸罩 | **两级结构**：点一下展开二级列表，11 款分两组 —— 7 款**头套**（中间有透明面孔开口，脸从开口里露出来）和 4 款**整脸覆盖**（没有开口，角色自己的脸把你整张脸盖住）。再点一下或按「收起」合上列表 |
| 自定义图片 | 选自己的 PNG，或者直接把图片拖到左边的预览画面上 |
| 自动跟随人脸 | 关掉之后图片固定在画面中间，用滑块手动挪到脸上 |
| 大小 | 图片宽度相对脸宽的倍数。内置头套默认 `2.47`（由面孔开口反推），整脸覆盖 `1.60`，自定义图片 `1.5`（后两者目标是盖住脸）。换脸罩会复位成对应默认值 |
| 左右 / 上下 | 相对脸的位置微调，上下正值是向下。每行右边的 `↺` 单独复位该项，卡片右上角的「全部复位」一次清三项 |
| 画面镜像 | 像照镜子一样左右翻转。翻转的是整帧，但**图片本身不会被左右翻过来**，所以带文字的表情包不会变成镜像字 |
| 显示人脸检测框 | 在预览上画出**人脸框（绿）/ 脸罩范围（品红）/ 面孔开口（青）**三个框。**只画在预览上，不会进视频**。用来排查「脸罩有没有对准脸」—— 见下面「排查问题」 |
| 分辨率 | 480p / 720p / 1080p 目标档；输出保持摄像头宽高比、不拉伸，摄像头达不到所选尺寸时不会放大 |
| 帧率 | 15 / 24 / 30 fps。低帧率会减少运动流畅度，同时减少文件体积和编码负载；默认 24fps |
| 画质 | 省空间 / 标准 / 高画质，根据分辨率与帧率调整 H.264 平均码率 |
| 声音来源 | 不录声音 / 只录麦克风 / 只录系统声音 / 两者都录 |

分辨率、帧率和画质会记住上次选择。录制面板显示当前设置下的大致每分钟文件大小；真实大小会因画面内容和音频略有差异。默认设置为 **720p / 24fps / 标准画质**。

**三者录制中不可修改** —— 摄像头预设和帧率中途改不了，强行改会让画面跳一下。想要换档，先停止录制。

## 内置脸罩素材

11 款素材都在 `Resources/Cover-*.png`，1024×1024、带透明通道的 PNG，文件名必须和
`Sources/HeadCover.swift` 里的 `id` 对得上。想加新款式，丢一张图进去、在 `HeadCover.all`
（或 `hoods` / `masks`）里加一行就行。

分两类，**锚点定义不同**，所以归一化的目标和默认缩放也不同：

| 类型 | 长什么样 | 锚点 | 默认缩放 |
|---|---|---|---|
| **头套** `Kind.hood` | 中间有透明面孔开口，脸从开口里露出来 | 开口 | 2.47（由开口宽反推） |
| **整脸覆盖** `Kind.mask` | 没有开口，角色自己的脸把你整张脸盖住 | 轮廓包围盒 | 1.60（按脸宽给倍数） |

当前库存：

- 头套：猪头 · 猫 · 熊猫 · 兔子 · 青蛙 · 骷髅 · 外星人
- 整脸覆盖：泰迪熊 · 柴犬 · 卡通猫 · 卡通熊猫

### 为什么必须归一化

`Compositor.drawOverlay` 是「按人脸宽度缩放、以人脸中心居中」贴图的。所以素材的锚点
**必须在画布正中心、且锚点宽占画布的比例对所有款式一致**，否则换一款就得重新调一遍大小和位置，
而且有的款脸根本框不住。实测原始素材差得很远：

| 素材 | 开口宽 / 图宽 | 洞心纵向位置 |
|---|---|---|
| 猪头 | 0.448 | 0.518 |
| 猫 | 0.429 | 0.526 |
| 青蛙 | 0.537 | 0.601 |
| 外星人 | 0.387 | 0.592 |

归一化把**头套**统一成「开口宽 336px」（开口宽/图宽 = 0.328），**整脸覆盖**统一成
「轮廓宽 963px」（轮廓宽/图宽 = 0.940），之后同类款式共用同一组默认参数。

`Tools/CoverNormalizer/main.swift` 就是干这个的。几何逻辑和 App、自检共用同一份
`Sources/CoverGeometry.swift`，所以规格只有一个来源，不会各写一份然后慢慢漂移：

```bash
# 编译（必须带上 CoverGeometry.swift）
swiftc -O -swift-version 5 -target "$(uname -m)-apple-macos14.0" \
  Sources/CoverGeometry.swift Tools/CoverNormalizer/main.swift -o .build/covertool

# 头套（默认）：锚点 = 面孔开口
.build/covertool analyze Resources/Cover-*.png        # 量每款的锚点宽高和位置
.build/covertool fit 1024 Resources/Cover-*.png       # 算「都不被裁切」能用的最大锚点宽
.build/covertool normalize /tmp/out 1024 336 <源图...> # 按锚点宽 336 归一化
.build/covertool verify /tmp/out/*.png                # 复查：锚点占比是否一致
.build/covertool preview /tmp/prev.png 2.47 Resources/Cover-*.png   # 合成到合成脸上，肉眼验收

# 整脸覆盖：锚点 = 轮廓包围盒（锚点宽 963）
COVERS_KIND=mask .build/covertool normalize /tmp/out 1024 963 <源图...>
```

`preview` 是最有用的那个 —— 它完全照 `Compositor` 的算法把素材盖到一张合成人脸上，
坐标推导对不对，看这张图就知道。

判定「锚点」时用 `alpha >= 128`（遮挡 50% 的位置），可以用 `COVERS_ALPHA` 覆盖。

> 判定「脸洞」时用的是 `alpha >= 128`（脸被遮挡 50% 的位置），不是 `alpha > 0`。
> 素材边缘是羽化的，用小阈值会把柔软的毛边也算成实体，量出来的洞远小于肉眼看到的开口。
> 阈值可以用环境变量 `COVERS_ALPHA` 覆盖。

## 排查问题

每次运行都会把采集参数和跟踪位置追加到 `~/Movies/FaceCover/诊断.txt`，长这样：

```
[2026-10-13T14:07:29Z] 采集连接 isVideoMirrored 原本=false 支持镜像=true 强制关闭后=false
[2026-10-16T00:52:11Z] 人脸中心=(0.514,0.512) 脸框=0.180×0.240 | 贴图中心=(0.514,0.512) 缩放=2.47×脸宽 | 镜像=开 | 逐帧检测=是 | 已追踪=是
```

每秒一行。**「人脸中心」和「贴图中心」应该永远相等** —— 贴图位置就是从人脸位置推导出来的。
如果这两个数不相等，才是真的 bug。

> 这行原来只记了 x，所以「位置不对」这类问题只能靠猜。现在把 y、脸框尺寸、贴图缩放
> 都记下来了，对着这行数字就能算出贴图到底落在哪、脸罩有多大。

**排查「脸罩没对准」最快的办法**：勾上「显示人脸检测框」，预览上会画出三样东西：

| 颜色 | 是什么 |
|---|---|
| 绿框 | Vision 检测到的人脸框（贴图就是按它的中心和宽度算的） |
| 品红框 | 脸罩实际占的画面范围 |
| 青框 | 脸罩素材里的**面孔开口** —— 脸应该正好落在这里面 |

外加一条青线连着两个中心。**青框里应该是你的脸**；如果脸偏到青框外面去了，那就是位置问题，
用「左右 / 上下」滑块调；如果青框本身就比你的脸小很多，那是大小问题，调「大小」。
三个框都只画在预览上，不会进视频。

## 自检

不存在「靠眼睛看着像对」这回事。四条链路都有无头测试，不需要摄像头、不需要任何权限：

```bash
./test.sh
```

1. **合成逻辑**（`Tests/Compositor/`）—— 真的构造像素缓冲区、把图片画进去，再逐像素采样，
   验证位置、缩放、偏移、镜像；包含「人脸横向移动时遮罩必须同向」的回归测试，
   以及「调试框画出来的开口就是脸露出来的位置」的像素级断言。
2. **录制管线**（`Tests/Recorder/`）—— 真的录出 `.mov`，再用 `AVAssetImageGenerator`
   把帧解回来逐像素确认脸被挡住、镜像方向正确。时间戳故意从一个大数值开始，验证开头没有空白。
   另外有一组 [0] 段专门验**录制质量档位**：分辨率降采样是否保持宽高比、摄像头达不到时是否不放大、
   竖屏和 4:3 源画面的取整、码率是否随画质档和帧率递增。
3. **人脸跟踪**（`Tests/Tracker/`）—— 喂正弦摆动的人脸，用互相关算相位延迟和同向比例；
   再喂**带随机噪声的静止人脸**，量输出的残余抖动。两条一起看，防止「为了压抖而引入延迟」。
4. **音频混音**（`Tests/Mixer/`）—— PCM 格式归一化、麦克风+系统声音相加、饱和处理、时间轴连续性、收尾不丢样本。
5. **录像库**（`Tests/Library/`）—— 真的录三段小视频丢进临时目录，验证扫描、排序、时长/大小读取、
   缩略图生成与缓存、以及删除会进废纸篓。
6. **脸罩素材**（`Tests/Cover/`）—— `HeadCover.all` 和 `Resources/Cover-*.png` 必须一一对应
   （防止加一行忘了放文件，或放了文件忘了加一行），再逐款校验锚点占比符合规格、内容不被裁切。

其中第 1 项的 [H] 段是最硬的一条：逐款比对「调试框算出来的锚点」和「脸实际露出来 / 被盖住的像素」，
11 款全部对上 —— 它同时验证了归一化、`measure`、`OpeningGuide.rect` 和 `drawOverlay` 四处的方向约定。

## 开发流程

`main` 分支有保护规则，**不能直接推**，改动一律走 PR：

```bash
git checkout -b fix/某个问题      # 从最新 main 开分支
# ...改代码...
./test.sh                        # 本地先跑自检
git commit -am "说明"
git push -u origin fix/某个问题
# 然后去 GitHub 开 PR，等 CI 绿了再合并
```

CI（`.github/workflows/ci.yml`）在 macOS runner 上跑 `./package.sh`，也就是
**生成图标 → 编译全部源码 → 82 项自检 → 出 DMG**，并把 DMG 作为构建产物上传。

> 注意 `./test.sh` 只编译被测试的那几个模块，**不覆盖 `CameraEngine` / `ContentView` 这些界面和采集代码**。
> 所以 CI 里额外跑了 `./build.sh`，不然 App 本身编译不过都发现不了。

## 几个实现上的坑（改代码前值得看）

- **坐标系**：Vision 的人脸框是「归一化 + 左下角为原点」，`CGBitmapContext` 架在
  `CVPixelBuffer` 内存上时原点也在左下角，而 buffer 第 0 行对应画面顶部 —— 三者天然对齐，
  **不需要**做 Y 轴翻转。乱加翻转会导致上下颠倒。
- **镜像和检测的先后顺序**：必须「先翻转整帧 → 再检测人脸 → 再贴图」。
  检测和贴图在同一个坐标空间里，遮罩和人脸才不可能分岔。
  把翻转做在贴图内部（第一版就是这样）会让「左右」滑块在开镜像时方向反掉。
- **采集连接不能重复镜像**：`AVCaptureConnection.automaticallyAdjustsVideoMirroring` 默认是 `true`。
  必须显式关掉，否则整帧会被翻两次，方向就乱了。诊断文件里会记录原始值。
- **色彩空间**：用 sRGB，不要用 `CGColorSpaceCreateDeviceRGB()`，否则贴上去的图片会被转换一次
  色彩空间，颜色发灰偏色（实测纯洋红 (1,0,1) 会变成 (255,64,255)）。
- **速度外推会放大噪声**：人脸框平滑里用速度做外推时，速度增益必须压得很低（0.20），
  否则逐帧检测噪声会被 `leadTime` 放大，人不动的时候遮罩反而更抖。
- **固定增益解决不了「静止抖」和「移动延迟」这对矛盾**：增益高则跟手但抖，低则稳但延迟。
  实测 α = 0.85 的指数平滑对**随机**噪声只把标准差降到 0.86 倍 —— 等于没压，
  静止时脸罩外缘逐帧位移 5.1px（1280 宽画面），肉眼明显在晃。
  现在按速度自适应：静止用 0.12，移动用 0.85，抖动降到 1px 以内，延迟仍是 0 帧。
  **写这类滤波器的自检时，噪声必须用随机值，不能用「±x 完美交替」的方波** ——
  方波是低通最容易压的信号，会一路绿灯却掩盖真实问题（这个坑踩过一次）。
- **歪头角度同样要自适应**：脸罩比脸大（`sizeScale` 约 2.5 倍），外缘位移 = 半径 × 角度，
  一点点角度噪声就会让脸罩边缘明显摆动。
- **检测节奏的降级必须带迟滞**：`detectEvery` 原来写的是单阈值 `cost > 0.015 ? 2 : 1`，
  耗时贴着阈值抖动时会每帧翻转，于是「一会儿每帧有检测、一会儿隔帧才有」，
  隔帧那帧只能靠外推 —— 运动节奏变得不匀，看起来也是「慌」。现在降级/恢复用两个阈值 + 连续帧数确认。
- **量脸罩素材的「面孔开口」不能用最大内切圆**：猪鼻子、猫嘴、兔牙、骷髅下巴都从下方凸进洞里，
  内切圆会被挤得远小于真实开口（猪头实测 155px vs 真实开口 457px 宽）。
  要用**中间那个透明连通域的外接矩形** —— 洪水填充会绕过凸出物，外接矩形恰好等于开口的完整边界。
- **量「面孔开口」的 alpha 阈值要取 128，不是 0**：素材边缘是羽化的，阈值太小会把柔软的毛边算成实体，
  区域在真正开口之前就被拦住，而且下方凸出物羽化更重，会把量出来的区域挤得偏上。
- **`CoverGeometry` 量出来的 y 是自素材顶部向下**，和直觉相反。别按「向上为正」去理解
  `OpeningGuide.offsetY`；`Tests/Compositor` 的 [H] 段有像素级断言专门盯着这个方向没搞反。
- **分辨率 / 帧率 / 画质录制中不可改**：`AVCaptureSession` 的预设和摄像头的帧率中途改不了，
  强行改会让画面跳一下。所以三处 `didSet` 都加了 `guard !isRecording else { return }`。
- **降采样要先按目标宽高比裁剪、再缩放**，不能直接拉伸 —— 摄像头给的是它自己的宽高比，
  和所选档位不一致时直接缩放会把画面压扁。另外 H.264 要求宽高是偶数，取整要朝偶靠。
- **摄像头帧率要在预设生效之后再设**：换分辨率会改变摄像头可选帧率范围，
  提前设可能被摄像头悄悄忽略。所以 `applyFrameRateLimit` 放在 `commitConfiguration()` 之后的 `defer` 里。
- **带 `didSet` 的 `@Published` 在 `init` 里不会触发**：录制质量三个属性是从 UserDefaults 读初始值的，
  初始化时不主动调一次 `syncSettings()` 的话，第一段录像会用默认档而不是用户上次选的档。
- **混音要等齐**：麦克风和系统声音是两条独立的数据流。只看到一路攒够一块就发出去，
  会把另一路同一时间段的样本整段丢掉。必须等两边都够（或某一路超时静音）再合成。
- **录制起头**：`AVAssetWriter` 的 `startSession` 要等到录制后的第一帧才调用，
  并传这一帧的时间戳，否则视频开头会多出一大段空白。
- **SwiftUI 宏**：这台机器只有 Command Line Tools，`SwiftUIMacros` 插件不存在，
  所以 **`@State` 用不了**（`@StateObject` / `@ObservedObject` / `@Environment` 是传统 property wrapper，没影响）。
  拖拽逻辑因此放在 AppKit 的 `PreviewNSView` 里，删除确认用 `NSAlert` 而不是 `.alert` 修饰符。
- **临时目录的 URL 陷阱**：`NSTemporaryDirectory()` 返回 `/var/...`，而 `contentsOfDirectory` 返回解析后的
  `/private/var/...`，两者字符串不相等。自检里比文件名而不是比完整 URL。

## 图标

`Tools/IconGenerator/main.swift` 用 CoreGraphics 直接画出来，没有任何外部图片素材：
深色相机镜头（六边形光圈）+ 一道斜着盖上去的橙色面罩（带两侧耳带）+ 右上角录制红点。

```bash
swiftc -O -o /tmp/genicon Tools/IconGenerator/main.swift
/tmp/genicon /tmp           # 产出 AppIcon.png（1024）和 AppIcon-preview.png（多尺寸预览）
```

`package.sh` 会自动调用它，用 `sips` 缩出全套尺寸、`iconutil` 打成 `.icns` 塞进 App 包。
改图标只要改这个 Swift 文件。

- **本机 Swift 版本和 CI 不一样**：本机是 Swift 6.4（Command Line Tools），
  CI 是 Swift 5.10（macOS runner 上的 Xcode）。同一个写法在 6.4 下能过，在 5.10 下可能是**硬错误**。
  已经踩过一次：

  ```swift
  var result: T?
  Task { result = try? await operation(); semaphore.signal() }
  semaphore.wait()
  ```

  Swift 5.10 报 `error: mutation of captured var 'result' in concurrently-executing code`。
  正确写法是用一个加锁的引用类型把结果传出来。**本地 `./test.sh` 全绿不代表能在 CI 上编译**，
  改完必须看 CI。

## 已知限制

- 只能录系统**输出**的声音，不能单独录某个 App 的声音
- 没有人脸的时候，图片会停在最后识别到的位置（这是故意的：宁可贴纸悬空，也不要突然露出脸）
- 这个 App 只能录它自己的摄像头画面。**Zoom / 腾讯会议 / 微信视频**里看到的是原始画面，
  不会带上脸罩 —— 那种需求要做虚拟摄像头（系统扩展 + 苹果开发者账号），是另一个量级的工作
